# Hakkı İzmirli — International Website (Cloudflare Pages)

**Deliverable:** an actual static multilingual website, not a mockup. Medical and contact facts are adapted from the doctor's existing website. The build currently includes **120 prerendered pages across 8 languages**.

## Project

- Target production domain: `https://hakkiizmirli.com`
- Target preview: **a separate Cloudflare Pages project**, e.g. `hakki-izmirli-web.pages.dev`
- Stack: static HTML + CSS + vanilla JavaScript generated by Python 3; no database, no package installation, no server-side framework.
- Languages: English, German, Arabic (RTL), Russian, Persian (RTL), French, Azerbaijani, Turkish.
- Turkish canonical homepage remains `/` to preserve the existing site's Turkish home URL. International audience uses `/en/` as the principal landing page. `x-default` points to English.
- Language-specific, server-rendered URLs with `<title>`, description, canonical, complete `hreflang`, OpenGraph, sitemap and JSON-LD Person/MedicalBusiness/MedicalWebPage.
- Functional mobile navigation, language switcher, FAQs, phone, email, WhatsApp and Google Maps. No fake appointment backend; form submission is intentionally NOT simulated.

## Local build and preview

```bash
python3 build.py
python3 -m http.server 8080 --directory public
# Open http://localhost:8080/en/
```

`build.py` writes all pages to `public/`, and regenerates SEO assets.

## Upload to Cloudflare Pages (direct upload)

1. Sign in to Cloudflare. Choose **Workers & Pages** → **Create application** → **Get started** → **Drag and drop your files**.
2. Create a **NEW Pages project**, e.g. `hakki-izmirli-web`. Do **not** edit the existing `kmvflmd` project.
3. Upload the **deployment ZIP** (`hakki-izmirli-cloudflare-upload.zip`) or drag the `public` folder. The ZIP must have `index.html`, `en/`, `de/`, etc. at its top level, not an extra parent folder.
4. Select **Deploy site** and visit your project’s `.pages.dev` URL. Check desktop/mobile language links, contact links and all images.
5. To release on `hakkiizmirli.com`, use the Pages project **Custom domains** tab **after** migrating all existing URLs and media, verifying MX/TXT DNS records are not altered, approving medical content and privacy text, and backing up the old site's hosting.

For a fully automated deployment use `npx wrangler login` and `npx wrangler pages deploy public --project-name hakki-izmirli-web` (the Pages project must already exist or Wrangler will guide creation).

**Cloudflare note:** a project originally created with Direct Upload cannot later be converted to Git integration. For long-term development, a fresh Git-integrated Pages project is preferable and can point at the same `public` output with build command `python3 build.py`, output directory `public`.

## SEO migration warning — do not skip

This is an impressive **client presentation / working v1 demo**, *not yet a safe drop-in replacement for every URL on the existing clinic website*.

Why: The existing site has many more long medical service pages and blog articles than the 120 new pages. Replacing production without a complete URL/content inventory would create 404s and lose existing SEO signals.

Before production cutover:

1. Export all pages, top-ranking queries, links and canonical URLs from current sitemap, Google Search Console and an actual site crawl.
2. Migrate high-performing original Turkish/English procedure articles and other legacy pages without changing their intent; obtain clinical and translated-content approval.
3. Extend `build.py` + `_redirects` for every old URL: use 301 only where there is a genuinely equivalent replacement; do not mass redirect unrelated medical pages to the homepage.
4. Preserve relevant URLs wherever possible (e.g. `/burun-estetigi/`, `/en/rhinoplasty/`).
5. Download every photo still referenced by the new site and any migrated long-form content.
6. Validate every language using native speakers/medical editors; healthcare content has elevated requirements for accuracy.
7. Confirm medical tourism authorization, permitted contact wording, privacy/KVKK/GDPR notices, consent and advertising-law compliance with a relevant professional.
8. During release validate the `.pages.dev` preview carries `X-Robots-Tag: noindex` while the live site is indexable. The `_headers` file contains Cloudflare-specific rules. Verify using `curl -I`.
9. Verify `robots.txt`, `sitemap.xml`, `hreflang`, canonical, 301 status codes, image responses, mobile CWV, and monitor Search Console for at least 4 weeks after migration.

## Security and privacy

- The site intentionally avoids a fake form. Email/WhatsApp/telephone links are real, but there is no claim that a message is stored by the demo.
- No analytics, tracking pixels or cookie banners are added without configuring a lawful and approved consent flow.
- Information is educational and makes no result guarantees, treatment assurances or unverified testimonials.
